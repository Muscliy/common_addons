# 工作流验收记录

本轮按原始需求第十六节的 17 个场景核对，使用隔离本地库。测试数据和普通 Project 任务均由测试创建。

| 原始验收项 | 验收结果 |
| --- | --- |
| 1–4 设计保存、刷新布局、无效图、发布校验 | 核心 ORM、HttpCase 及浏览器组件测试覆盖 |
| 5 循环检测 | 发布拒绝环和不可达节点，受控循环退回待实现 |
| 6–7 顺序推进及条件选择 | 核心运行测试覆盖，采购示例验证 4999 和 5000 |

| 10–11 人工办理及并行汇合 | 核心测试覆盖，模具示例验证 Project 与人工任务都到齐才继续 |
| 12–13 幂等和并发 | 独立数据库连接覆盖流程启动、人工任务、汇合、审批及 Project |

本轮补齐版本回退。发布人员在模板版本列表确认“启用此版本”，系统在事务内重新校验并切换当前版本。模板显示最近启用人及时间。既有发布记录保持冻结，新草稿从当前启用版本复制。画布启动时传入所见版本 ID，已完成的相同启动请求仍可按原请求标识重试。

## 可复现的示例

示例在 [验收测试](../workflow_project/tests/test_acceptance_examples.py) 中通过真实 ORM 创建、发布、启动和办理。可在装有三个工作流模块的隔离库运行 `--test-tags=/workflow_project:TestAcceptanceExamples`，或在画布按以下顺序配置。

- **采购审批**。开始 → 部门审批 → 金额条件。小于 5000 走默认出口结束，大于等于 5000 进入财务审批后结束。测试使用联系人 `color` 字段模拟金额输入，实际采购单集成待实现。
- **模具开发**。客户需求作为起点，完成模具设计和技术审批后同时开启采购 Project 任务与加工待办。两支汇合后进入试模和品质审批。测试确认采购先完成时试模尚未创建。实际生产、采购和质量单据集成待实现。

## 仍缺的交付

| 范围 | 尚未覆盖 |
| --- | --- |
| 审批 | 组内任一人通过已支持。多人会签、指定节点驳回、申请撤回、转交和审批超时提醒待实现 |
| 人工待办 | 有个人待办、已办、意见和实例取消。跨类型统一任务中心、用户组领取、开始办理状态、单任务转交/退回/取消、截止日期、提醒和附件待实现 |
| 设计与执行 | 自动动作白名单、通知节点、执行试跑、条件满足式汇合、受控循环及持久异常恢复待实现。节点说明、通用进出条件、时限和通知策略仍缺 |
| 监控 | 已有执行状态、时间、意见、审计及业务单据入口。节点级权限配置、异常节点状态和管理设置待实现 |
| 业务 | 联系人及 Project 已接入。采购、销售、制造和质量单据属于后续适配 |
